## 1. 產品定位與名詞

MyFSL 是「年度計畫 × 半月現金流」的個人記帳 App。日常打開直接進入**記帳**；每週一次**本週檢查**對帳補漏；需要做決定時用**試算**比較不同情境的未來現金水位。

| 名詞 | 定義 |
|---|---|
| 期別（半月） | 現金流的最小單位。每月分**上半月**（1–15 日）與**下半月**（16 日–月底），一年 24 期 |
| 項目 | 預算的一個科目，例如「生活費」。分收入、支出、轉帳三種 |
| 計畫列 | 支出為「項目 × 支付方式」，例如「生活費・現金」；收入與轉帳沒有支付方式 |
| 支付方式 | 現金、信用卡、轉帳。預算依支付方式歸屬；刷哪一張卡是選填 |
| 時點 | 金額落在上半月、下半月，或上下各半 |
| 固定／可調 | 可調項目才列入「本月可調支出」進度控管與反推目標 |
| 追蹤方式 | 每月固定、依記帳、每週回報、到期確認 |
| 本月到期 | 每月固定的項目、貸款月繳、卡片利息與繳款、分期各期：到期時列在記帳畫面，使用者點一下選支付方式才記下，App 不會自己寫入（R-DUE） |
| 延期款 | 到期確認時選「延到下月」的未付金額，獨立記錄、金額固定，到期再確認（R-DEF） |
| 依合約繳款 | 信用卡有循環條件、貸款有攤還條件時，每月繳款金額由條件算出，列在本月到期 |
| 額外還款 | 計畫裡轉給「依合約繳款」的卡片或貸款、且勾了「額外還款」的轉帳；沒勾就不計，避免重複（R-PAY-01） |
| 預設卡片 | 刷卡沒指定卡片、計畫的刷卡金額，都算在這張卡上；設定可選，沒選時為排序第一張卡 |
| 帳戶對帳 | 本週檢查時比對「實際金額」與「App 推算」：數錢包、看銀行餘額、看各張卡欠款 |
| 漏記差額 | 對帳後發現實際比記帳多花的部分，存成一筆記帳並歸到某個項目 |
| 流動資金（現金水位） | 現金、銀行存款、儲值卡餘額合計 |
| 信用卡合計 | 本週檢查對帳時，所有卡片合併成一列（每張卡各填欠款）。試算與帳戶頁逐卡計算 |
| 循環利息 | 沒有全額繳清時，未清餘額每月產生的利息，會加進卡債 |
| 最低應繳 | 帳單上最少要繳的金額，含當期循環利息；只繳這個金額時本金減得很少 |
| 分期 | 一筆刷卡消費分成 N 期入帳。刷卡當下**全額佔用額度**，帳單每期入帳一期金額 |
| 已佔用額度 | 目前欠款 ＋ 未入帳的分期本金；和「要繳的卡債」不是同一個數字 |
| 結構缺口 | 每年「收入 − 支出 − 貸款本金還款」；支出含貸款利息、循環利息與分期手續費，不含新借款、一次清償與分期本金入帳 |

## 2. 資料模型

### 2.1 帳戶 Account

| 種類 | 性質 | 餘額意義 |
|---|---|---|
| 現金 CASH、銀行存款 BANK、儲值卡 STORED_VALUE | 流動資產 | 持有金額 |
| 信用卡 CREDIT_CARD | 負債 | 欠款（正數 = 欠錢）；可設額度、繳款日 |
| 貸款 LOAN、保單借款 POLICY_LOAN | 負債 | 欠款；可設攤還條件 |

攤還條件 LoanTerms：年利率、剩餘期數、攤還方式（本息平均／本金平均／只繳利息）、扣款帳戶、繳款日、原貸金額（選填）。

信用卡的細節**全部選填**，使用者自己決定填多少：只填名稱與欠款時，卡片就只是一個餘額，不計息、繳款照計畫走（還清後不再扣款，R-PAY-02）。
帳戶另有選填的**發卡銀行**。

循環條件 CardTerms（信用卡選填；沒設定就不計息，繳款完全由計畫中的「繳卡費」決定）：

| 欄位 | 預設 | 說明 |
|---|---|---|
| 循環年利率 | — | 未清餘額每月計息 |
| 最低應繳比例 | 10% | 未清餘額 × 比例 |
| 最低應繳下限 | $1,000 | 比例算出來太小時的下限 |
| 繳款方式 | 最低應繳 | 固定金額／最低應繳／當期全額 |
| 固定金額 | — | 繳款方式為「固定金額」時的月付金 |
| 扣款帳戶 | — | 未設定時用支付方式「轉帳」的帳戶 |
| 計息與繳款日 | 15 | 決定落在上半月或下半月 |
| 結帳日 | — | 選填，用來顯示與推估分期入帳月份 |
| 既有卡循 | — | 選填；目前欠款中已在計息的部分，只影響第一次計息（R-CARD-13）。第一次自動計息後清掉 |

### 2.2 計畫 Plan

- `PlanItem`：名稱、群組、種類、入帳／轉出帳戶、轉入帳戶、時點、**日期**（每月幾號，選填）、固定／可調、追蹤方式、**額外還款**、封存與**封存月份**。
- 日期：每月固定的項目在這一天到期；沒填時上半月當 1 號、下半月當 16 號、上下各半兩天都有。短月份取月底。
- `PlanLine(itemId, method)`：支出一定有支付方式；收入、轉帳為 null。
- 每個計畫列每年 12 個月金額。某年度沒有計畫時，沿用最接近的前一年度；再沒有則用最早年度。**R-PLN-01**

追蹤方式決定「本月花多少」怎麼來：

| 追蹤方式 | 用在哪種項目 | 本月金額怎麼算 |
|---|---|---|
| 每月固定 | 固定帳單與固定收入，例如停車費、手機網路、薪資 | 到期時列在記帳畫面的「本月到期」，點一下選支付方式記下（R-DUE）；已經自己記的部分會扣掉 |
| 依記帳 | 可調項目，例如生活費 | 記帳加總；漏的靠帳戶對帳補 |
| 每週回報 | 現金分信封，或能單獨查到金額的項目 | 每週回報還剩多少或累計多少 |
| 到期確認 | 不定期項目，例如汽車保養、年終獎金 | 到期時確認實際金額 |

### 2.3 實際數字

- `LedgerEntry`（記帳）：日期、種類、金額、項目、支付方式、帳戶（刷卡未指定卡片時為空）、轉入帳戶、備註、**來源**、寫入時間。
  來源分四種：**自己記的**（負數為退款）、**漏記差額**（對帳產生）、**到期確認**（補記，含延期款付款）、**到期記下**（在本月到期點下的，R-DUE）。
  到期記下的與延期款付款帶**識別碼**（postingKey），例如 `plan:101:-:2026-09:15`、`cardint:3:2026-09`、`loan:5:2026-09`、`inst:7:1`、`deferral:4`；同一個識別碼只會有一筆，記下後不再列出。
- `PostedKey`：選了「這個月沒有」的到期項目識別碼，之後不再列出。
- `Deferral`（延期款）：項目、支付方式、原本月份、到期月份、金額、是否已付清（R-DEF）。
- `ItemActual`：某計畫列某月的**狀態**（已完成／延到下月），由到期確認寫入。金額不存在這裡。
- `BalanceSnapshot`：帳戶某天的校正餘額，含寫入時間。

### 2.4 分期 CardInstallment

一筆分期消費自己帶條件（因為每次消費的期數與費率都不同）：卡片、預算項目、消費日、總金額、期數、費用方式與數值、第一期入帳期別、是否已結清。

費用方式四種：**0 利率**、**每期手續費**（固定金額）、**總額手續費率**（總金額的百分比，平均分到各期）、**年利率**（依剩餘本金逐期計息）。

## 3. 共用規則

### 3.1 金額與期別

- **R-FMT-01** 金額一律為新台幣整數元（Long）。`$12,345`、`−$12,345`（負號為 U+2212）、正數差額加 `+`。
- **R-FMT-02** 精簡格式：未滿一萬原樣顯示；一萬以上換成「萬」保留一位小數並去掉 `.0`（`12.3萬`、`12萬`）；一百萬以上不留小數（`150萬`）。
- **R-FMT-03** 輸入解析允許逗號與空白；空字串或非數字視為無效。
- **R-PER-01** 1–15 日為上半月，16 日起為下半月。
- **R-PER-02** 期別序號 = 年 × 24 + (月 − 1) × 2 + 半月（上 0、下 1），用於排序、跨年加減與儲存。標籤「9月上」、全名「2026年9月上半月」。
- **R-PER-03** 時點拆分：上半月全額在上、下半月全額在下；上下各半時奇數的 1 元放在下半月。
- **R-PCT-01** 百分比以十進位四捨五入到整數（0.145 → 15）。

### 3.2 支付方式與帳戶對應

- **R-ACC-01** 現金 → 設定的現金帳戶（須為未封存的流動帳戶）→ 第一個現金帳戶 → 第一個流動帳戶。轉帳 → 設定的轉帳帳戶 → 第一個銀行帳戶 → 第一個流動帳戶。
- **R-ACC-02** 信用卡：「指定信用卡」開啟時為所選卡片（可選「不指定」）；關閉時一律不指定。
- **R-ACC-03** 收入入帳到項目的入帳帳戶；轉帳由轉出帳戶到轉入帳戶。
- **R-ACC-04** 帳戶種類對應的支付方式（對帳時把差額歸到項目用）：現金與儲值卡 → 現金；銀行存款 → 轉帳；信用卡 → 信用卡。

### 3.3 實際花費與餘額

- **R-ACT-01** 計畫列某月的實際金額 = 當月該列**所有記帳的合計**，包含對帳產生的漏記差額與到期確認的補記。
- **R-ACT-02** 計畫列的狀態只有到期確認會寫入：已完成、延到下月。
- **R-ACT-03** 帳戶餘額 = 最近一次校正餘額 ＋ 校正之後記帳的影響。「之後」＝ 日期較晚，或同一天但寫入時間較晚。
- **R-ACT-04** 記帳對帳戶的影響：收入加、支出減、轉帳轉出減轉入加；負債帳戶方向相反（刷卡使欠款增加、繳卡費使欠款減少）。
- **R-ACT-05** 未指定卡片的刷卡：晚於最近一次「**全部卡片一起對帳**」（每張未封存的卡都有同一個寫入時間的校正）的部分，加進卡債合計；試算時算在預設卡片上。只校正其中一張卡時不吸收，因為不知道那些刷卡是不是刷那張卡。分期消費本身不算（由各期入帳）。
- **R-ACT-06** 本月支出、收入與預算進度都不算**分期本金入帳**（消費當月已經算過全額）；分期手續費算。

### 3.4 本月到期、繳款來源與延期款

**本月到期（R-DUE）**：App 不會自動寫入任何記帳，到期的款項由使用者點一下記下。
- **R-DUE-01** 列出的款項：追蹤方式為「每月固定」的計畫列（依日期）、有攤還條件的貸款（本金＋利息一個項目）、有循環條件的卡片（循環利息、繳卡費各一個項目）、分期各期（本金＋手續費一個項目）。金額依計畫與合約算好帶入：前面的項目記下後，後面的建議金額（例如最低應繳含剛計的利息）跟著算，順序見 R-ORD-01。卡片的起始欠款和試算相同：未指定卡片的刷卡算在預設卡片上（R-ACT-05）。
- **R-DUE-02** 範圍：到期日**晚於起算日、不晚於本月底**，還沒記下、也沒選「這個月沒有」。起算日 = 第一次開啟 App 那天（那天輸入的餘額已經包含之前的款項）；清除資料後重設、載入示意資料時為當天、從備份還原時沿用備份裡的起算日（舊備份沒有時為當天）。上個月以前到期還沒記下的標「逾期」。
- **R-DUE-03** 點一下記下：金額可以改（分期不能改）；支出選支付方式（現金／信用卡／轉帳，預設計畫的；刷卡時再選卡，或不指定），收入選入帳帳戶，轉帳、貸款、繳卡費選扣款帳戶（必須是現金或存款帳戶）。貸款改金額時利息不變、差額算本金（少繳時不會出現負本金；沒繳到的利息不另外記，期數照樣減一）。**付款日預設今天**；到期日在今天以前時可以改選「到期日」（到期當天就付了、現在才補記）。付款日決定影響哪一次校正之後的餘額；屬於哪個月的預算看識別碼裡的月份，逾期才付也算原本的月份。記下時貸款剩餘期數減一、第一次記下利息時清掉既有卡循（並記下原值，刪除時恢復），和記帳在同一個交易內寫入；連點兩次不會記兩筆。
- **R-DUE-04** 不重複：每個項目有唯一識別碼，同一組識別碼（貸款本金與利息、分期本金與手續費）任何一個記下或選「這個月沒有」後就不再列出（只繳利息的貸款只有利息那一筆也算）。自己在記帳畫面記了一部分時只列剩下的：同一支付方式的記帳，加上這個項目沒規劃的支付方式的記帳（例如計畫轉帳、實際付現金）；沒規劃的金額依計畫列順序分配，每一筆只抵一次。該列本月已確認完成或已延期就不列。刪掉到期記下的記帳，這個項目會回到清單（R-REC-EDIT-07）。
- **R-DUE-05** 本週檢查的第一步先列出到期（今天或之前）還沒記下的項目：已付（收入稱已入帳）／金額不同／這個月沒有。清單依已經選的項目往下算：還沒選或選「這個月沒有」的不算進後面的建議金額（例如略過利息後，全額繳款就少那筆利息），畫面預覽和最後寫入用同一份結果。付款日為檢查當天。在對帳之前處理，對帳的推算已經包含它們，才不會被當成漏記。本期的檢查提醒把它們算進到期確認的項數。
- **R-DUE-06** 試算：到期還沒記下的放在今天所在的半月；已經記下的不再預測；本月還沒到期的依到期日放（R-FC-03）。

**繳款來源（R-PAY）**
- **R-PAY-01** 同一筆負債的每月繳款只有一個來源：卡片有循環條件、貸款有攤還條件時，**依合約**算出每月繳款（列在本月到期）；計畫裡轉給這些負債的轉帳**不計入**（年度彙總、試算、本月到期都不算），除非項目勾了「額外還款」。計畫檢查與項目編輯會提醒。沒有條件的卡片與貸款，繳款完全照計畫。
- **R-PAY-02** 還款最多還到欠款為 0：轉給負債的款項（計畫轉帳、額外還款、固定金額繳款）超過當時欠款時只繳到 0，多的錢留在原帳戶。試算與本月到期的建議金額都適用；年度計畫表仍照計畫原樣彙總，計畫檢查會提示「全年計畫比目前欠款多」。

**延期款（R-DEF）**
- **R-DEF-01** 到期確認選「延到下月」：本月該列標為延期，還沒付的金額（計畫 − 已記帳）變成一筆**延期款**，下個月到期。原本月份的計畫不再計入。
- **R-DEF-02** 延期款到期（或過期未付）時出現在到期確認，金額固定：已付 → 記一筆（來源：到期確認，識別碼 `deferral:id`）並結清；金額不同 → 記實際金額並結清；再延一次 → 只改到期月份。
- **R-DEF-03** 試算：未付清的延期款，到期月份是本月或更早的放在今天所在的半月；之後的在到期月份依項目的時點與日期放入。調整、停止等情境不影響延期款（R-SC-01）。

**事件順序（R-ORD）**
- **R-ORD-01** 同一天（本月到期的建議金額）或同一個半月（試算）內的處理順序，兩邊一致：

  | 順序 | 事件 | 說明 |
  |---|---|---|
  | 1 | 分期各期入帳 | 本金與手續費先變成卡債，後面的計息與繳款才看得到 |
  | 2 | 循環利息 | 依當時欠款（或第一次的既有卡循）計息 |
  | 3 | 全額清償（情境） | 金額 = 當時欠款 |
  | 4 | 卡片繳款 | 最低應繳／固定金額／當期全額，依當時欠款 |
  | 5 | 貸款月繳 | 本金與利息 |
  | 6 | 其他收支與轉帳 | 計畫項目、延期款、一次性收支；轉給負債的受 R-PAY-02 限制 |

  試算的保守最低水位另把同一半月的支出都視為發生在收入之前（R-FC-09）。

## 4. 功能規則

### 4.1 記帳（開啟 App 的第一個畫面）

**金額鍵盤**
- **R-ENT-01** 按鍵 1–9、0、00、倒退。去掉前導 0；超過 7 位數時整次按鍵忽略（999,999 再按 00 仍是 999,999）。沒有輸入時顯示 0。

**預設值**（選項目時帶入）
- **R-ENT-02** 支付方式：這個項目上次用的 → 本月計畫金額最大的 → 第一個計畫列 → 現金。收入、轉帳沒有支付方式。
- **R-ENT-03** 卡片：「指定信用卡」開啟時為這個項目上次刷的卡（該卡已封存或上次未指定則為「不指定」）；關閉時不指定。
- **R-ENT-04** 「上次用的」只看自己記的那幾筆，對帳差額與到期確認補記不算。
- **R-ENT-05** 切換項目或收支種類時，清空備註；金額保留。再點目前的支付方式不會重設卡片。

**預算提示**（金額下方一行）

| 情況 | 文字 | 警示色 |
|---|---|---|
| 有計畫、未輸入、未超支 | `生活費・現金 本月剩 $4,600` | 否 |
| 有計畫、未輸入、已超支 | `家用・現金 本月已超出 $300` | 是 |
| 有計畫、輸入後仍有剩 | `記下後 生活費・現金 剩 $4,480` | 否 |
| 有計畫、輸入後超出 | `記下後超出 生活費・現金 計畫 $7,400` | 是 |
| 項目有計畫但沒規劃這個支付方式 | `生活費沒有規劃用轉帳，會算進生活費總額（剩 $10,800）` | 是 |
| 項目本月沒有任何計畫 | `不在本月計畫內，會列入計畫外支出` | 否 |
| 收入、轉帳 | `不影響支出進度` | 否 |

- **R-ENT-06** 上表的「剩」= 計畫 − 實際（R-ACT-01）。未規劃支付方式的「總額剩」= 項目各支付方式計畫合計 − 項目全部實際（含未規劃的支付方式）− 本次金額。

**記下**
- **R-ENT-07** 金額為 0 時「記下」停用（文字「輸入金額後記下」）；有金額時為「記下 $1,200」。
- **R-ENT-08** 建立記帳：支出帶支付方式與扣款帳戶（R-ACC-01/02）；收入帶入帳帳戶；轉帳帶轉出、轉入帳戶；備註去除前後空白；來源為「自己記的」，寫入時間由 repository 蓋上。
- **R-ENT-09** 記下後提示（4 秒自動消失，含「復原」）：`已記下 早餐 $85 · 生活費・現金剩 $4,515`。沒有備註時用項目名稱；非計畫的支付方式、收入、轉帳不附剩餘；剩餘可為負（`剩 −$400`）。
- **R-ENT-10** 記下後清空金額與備註，保留項目與支付方式，方便連續記帳。連續記下重新計時。
- **R-ENT-11** 復原：移除剛記下的那一筆；不會刪到更早的紀錄。
- **R-ENT-12** 上方提示列：`9/14 今天已記 3 筆 · $655`，只計今天**自己記的**支出；右側顯示「生活類每日可用」（該群組各列每日可用加總，R-BUD-05）。
- **R-ENT-13** 退款：支出可切換「退款」，存成負數，退回原付款帳戶或卡片，並減少該項目本月花費；紀錄標「退款」。收入與轉帳沒有退款。

### 4.2 本週檢查（三步）

一個錢包也能用：不必分信封，只要數錢包總額、看銀行餘額與各張卡欠款。

- **R-CHK-01** 三個步驟：到期確認 → 帳戶對帳 → 確認要寫入什麼。有分信封或能單獨查到金額的項目，才會多一段「每週回報」（R-CHK-11）。

**到期確認**
- **R-CHK-02** 列出追蹤方式為「到期確認」、本月有計畫金額、尚未完成也未延期的列（收入、轉帳也包含）。
- **R-CHK-03** 三個選項：
  - 已付（收入稱「已入帳」）→ 以計畫金額為實際。
  - 金額不同 → 必須輸入實際金額。
  - 延到下月 → 標為延期，未付金額變成延期款（R-DEF-01），不產生記帳。
  前兩者會補記「實際金額 − 本月已記帳」的差額（來源：到期確認），並把該列標為已完成。已經記過帳就只補差額。延期款到期時的選項見 R-DEF-02。

**帳戶對帳**
- **R-CHK-04** 對帳列：每個流動帳戶各一列；所有信用卡合併成「信用卡合計」一列（因為未指定卡片的刷卡無法歸到單張卡），並要求每一張卡都填欠款。推算欠款 = 每張卡的欠款 ＋ 本次檢查記下的影響（利息、繳卡費、分期各期、指定卡片的刷卡）＋ 未指定卡片的刷卡。「填入各卡推算欠款」把每張卡含本次影響的推算欠款填進去（未指定卡片的刷卡不知道是哪張卡，要自己加）；每張卡一起寫入的校正，就是 R-ACT-05 的「全部卡片一起對帳」。
- **R-CHK-05** 每列的「App 推算」已包含前面步驟產生的補記。差額算法：
  - 資產帳戶：差額 = 推算 − 實際（正數代表錢變少，也就是漏記）。
  - 信用卡：差額 = 實際欠款 − 推算欠款（正數代表欠更多，也就是漏記）。
- **R-CHK-06** 差額分類與訊息（銀行顯示的卡片欠款只會比實際少，因為有些刷卡還沒入帳）：

  | 分類 | 條件 | 訊息 | 預設處理 |
  |---|---|---|---|
  | 已對帳 | 差額 = 0 | `和推算一樣` | 只校正餘額 |
  | 漏記 | 差額 > 0 | 資產：`少了 $500，可能是漏記`；信用卡：`銀行多 $650，可能有刷卡沒記` | 歸到項目 |
  | 可能還沒入帳 | 信用卡欠款比推算少，且差額 ≤ 最近幾天記的刷卡 | `銀行少 $1,000，可能是最近 5 天的刷卡還沒入帳` | 先不處理 |
  | 可能記重複 | 其他（比推算多） | 資產：`多了 $300，可能是記重複或有收入沒記`；信用卡：`銀行少 $12,101，可能是記重複或有退款` | 只校正餘額 |

- **R-CHK-07** 三種處理方式：
  - 歸到項目 → 差額存成一筆記帳（來源：漏記差額），並寫入校正餘額。差額為負時存成負數（多記差額）。
  - 只校正餘額 → 只寫入校正餘額，不影響任何項目進度。
  - 先不處理 → 什麼都不寫，下週再對。
- **R-CHK-08** 「歸到項目」的預設項目 = 本月這個支付方式計畫金額最大的**可調**項目；沒有可調項目時取計畫最大的支出項目；再沒有就取有這個支付方式計畫列的第一個項目。使用者可以改。
- **R-CHK-09** 沒有填實際金額的帳戶跳過；信用卡合計少填一張卡就整列跳過。
- **R-CHK-10** 完成檢查時，對帳記帳、到期確認補記與校正餘額以**同一個寫入時間**寫入，並新增一筆檢查紀錄。校正餘額因此已包含這些記帳，不會重複扣。

**每週回報（有分信封時）**
- **R-CHK-11** 追蹤方式為「每週回報」的支出列，本月有計畫或已有記帳時列出：現金問**還剩多少**（預填 = 計畫 − 已記帳，最低 0），其他支付方式問**累計花費**（預填 = 已記帳）。回報值與已記帳的差額存成漏記差額（負數為多記差額）。

### 4.3 本月可調支出進度

- **R-BUD-01** 對象：未封存、可調的支出項目；每列為「項目 × 支付方式」，包含有計畫的支付方式，以及本月有記帳或確認過的支付方式。計畫與實際皆為 0 的列不顯示。
- **R-BUD-02** 時間進度：上下各半 = 今天 ÷ 當月天數；上半月 = 今天 ÷ 15（最多 1）；下半月 = (今天 − 15) ÷ (當月天數 − 15)（0 到 1）。
- **R-BUD-03** 花費進度 = 實際 ÷ 計畫；計畫為 0 但有花費時視為 100%。超前幅度 = 花費％ − 時間％（兩者先各自四捨五入）。
- **R-BUD-04** 狀態依序判斷：

  | 順序 | 條件 | 狀態 |
  |---|---|---|
  | 1 | 到期確認已完成 | 已完成 |
  | 2 | 本月沒有計畫 | 未規劃 |
  | 3 | 實際 > 計畫 | 已超支 |
  | 4 | 時間進度 0% 且尚未花費 | 尚未開始 |
  | 5 | 超前幅度 > 10 個百分點 | 花太快 |
  | 6 | 其他 | 正常 |

- **R-BUD-05** 剩餘 = 計畫 − 實際（最低 0）。每日可用 = 剩餘 ÷ 含今天在內的剩餘天數（無條件捨去）；已用完、已完成、未規劃或時間已過時不顯示。剩餘天數：上下各半 = 當月天數 − 今天 + 1；上半月 = 15 − 今天 + 1（最低 0）；下半月 = 當月天數 − max(今天, 16) + 1。
- **R-BUD-06** 排序：已超支 → 花太快 → 正常 → 尚未開始 → 未規劃 → 已完成；同狀態超前多的在前。
- **R-BUD-07** 項目合計包含未規劃支付方式的花費。

### 4.4 年度計畫表

- **R-PLS-01** 彙總：
  - 全年收入、全年支出。
  - 刷卡（支付方式 = 信用卡）與非刷卡支出（現金＋轉帳）。
  - 繳卡費：有循環條件的卡依合約（以目前欠款估算每月一筆：固定金額／最低應繳／當期全額）＋ 轉帳到信用卡的計畫（依 R-PAY-01，只有沒條件的卡或額外還款才算）。
  - 貸款繳款：有攤還條件的貸款以目前每月應繳 × 12 估算 ＋ 轉帳到貸款或保單借款的計畫（同樣依 R-PAY-01）。
  - 循環利息：**逐卡**以目前欠款（有既有卡循時用它）估算每月一筆，沒有循環條件的卡不計息。
  - 封存的項目只算封存月份之前（R-EDT-10）。年度彙總照計畫原樣，不套用 R-PAY-02 的上限。
- **R-PLS-02** 月現金流 = 收入 − 非刷卡支出 − 繳卡費 − 貸款繳款。當月卡債變化 = 刷卡 ＋ 循環利息 − 繳卡費。卡債全年增加 = 全年刷卡 ＋ 全年循環利息 − 全年繳卡費。結構缺口 = 全年收入 − 全年支出 − 全年貸款繳款 − 全年循環利息。
- **R-PLS-03** 群組小計只加支出，依群組順序排列。
- **R-PLV-01** 計畫檢查，錯誤排在最前：

  | 嚴重度 | 訊息 |
  |---|---|
  | 錯誤 | `「x」沒有設定入帳帳戶` |
  | 錯誤 | `「x」沒有設定轉出帳戶`／`「x」沒有設定轉入帳戶` |
  | 錯誤 | `「x」轉出與轉入是同一個帳戶` |
  | 錯誤 | `支付方式「現金」沒有對應的帳戶，請先新增現金帳戶或在設定指定`（轉帳同理，改為「銀行帳戶」） |
  | 警示 | `「x」不計入：「信貸」已依合約自動繳款。若這是額外還款，請在項目勾選「額外還款」`（卡片同理，R-PAY-01） |
  | 警示 | 逐卡：卡債會變多時的提醒，前面加卡名，例如 `「信用卡 A」每月刷 …`（R-CARD-05；計畫的刷卡算在預設卡片） |
  | 警示 | `全年刷卡加利息比繳卡費多 $23,980，差額會累積成卡債` |
  | 警示 | `計畫有刷卡，但還沒有信用卡帳戶；試算時先用一張沒有利息的替代卡片` |
  | 警示 | `計畫中沒有任何收入` |
  | 提示 | `「x」是額外還款：除了「信貸」依合約的月繳之外另外計入` |
  | 提示 | `「繳信用卡 B」全年 $108,000，比「信用卡 B」目前欠款 $45,000 多；還清後試算與本月到期就不再扣款`（R-PAY-02；不是預設卡片、不會再增加欠款的負債才提示） |
  | 提示 | `「x」今年沒有任何計畫金額` |
  | 提示 | `「x」是可調項目，建議改成依記帳，才能控管進度`（可調＋每月固定） |

### 4.5 帳戶與負債

- **R-ACV-01** 信用卡：使用率 =（欠款 ＋ 未入帳分期本金）÷ 額度（0–100%）；可用額度 = 額度 − 欠款 − 未入帳分期本金（最低 0，R-CARD-09）；本月已刷 = **指定這張卡**的本月自己記的支出（含分期消費全額；不含利息與各期入帳；未指定卡片的不算在任何一張）；本月預計繳款 = 有循環條件時依合約（＋額外還款），沒有時為本月計畫中繳這張卡的金額；有循環條件時另外顯示當期利息與最低應繳（R-CARD-01/02）。未指定卡片的分期算在預設卡片上。
- **R-ACV-02** 貸款：每月約繳 = 有攤還條件時為攤還表第一期，否則為本月計畫繳款；已還比例 = (原貸 − 餘額) ÷ 原貸，沒有原貸時不顯示。
- **R-ACV-03** 總覽：可動用現金 = 流動帳戶合計；已入帳卡款 = 各卡欠款 + 未指定卡片刷卡；**信用卡總負債 = 已入帳卡款 ＋ 未入帳分期本金**（已經消費、之後每期一定會入帳）；負債合計 = 信用卡總負債 + 貸款 + 保單借款。
**循環信用**
- **R-CARD-01** 當期循環利息 = 未清餘額 × 年利率 ÷ 12（四捨五入到元）。餘額或利率為 0 時沒有利息。
- **R-CARD-02** 最低應繳 = max(下限, 未清餘額 × 比例, 當期利息)，最多為全部欠款。
- **R-CARD-03** **逐卡計算**：每張有循環條件的卡在自己的計息與繳款日，用自己的利率、最低應繳比例與下限、繳款方式與扣款帳戶計算（不能合併成一張卡再算：A 欠 500、B 欠 100,000、下限 1,000、比例 10% 時，逐卡最低應繳 500 ＋ 10,000 = 10,500，合併算會變成 10,050）。計畫的刷卡與未指定卡片的刷卡算在預設卡片上；要分卡就在記帳時指定卡片。只有對帳時合併成「信用卡合計」一列（R-CHK-04）。
- **R-CARD-04** 本月卡債變化 = 新刷卡 ＋ 循環利息 − 繳卡費。繳款先付利息，剩下的才還本金：還到本金 = max(0, 繳款 − 利息)；繳款不夠付利息時，沒付到的利息留在卡債裡（還到本金是 0，不是負數）。
- **R-CARD-05** 卡債會變多時（變化 > 0）顯示提醒，並算出每月**至少**還要多繳多少，卡債才**不會再增加**（多繳這個數字時剛好持平；要下降還得再多繳）：
  - 繳款 ≤ 利息：`繳的錢還不夠付循環利息 $5,000，卡債只會變多；每月至少要多繳 $22,000 卡債才不會再增加`
  - 繳款 > 利息但仍不夠：`每月刷 $20,000、利息 $5,000，繳 $20,000 不夠；每月至少要多繳 $5,000 卡債才不會再增加`
  - 計畫檢查逐卡提醒時，訊息前面加卡名（R-PLV-01）。
- **R-CARD-06** 「只繳最低應繳、不再刷卡要多久還完」：逐月試算；若餘額不再下降則回報「還不完」。
**分期**
- **R-CARD-13** 既有卡循（選填）：目前欠款中已經在計息的金額（帳單上前期沒繳清的部分）。有填時，**第一次計息**以既有卡循為準（不超過欠款），帳戶頁的當期利息也用它；之後沒繳清的欠款全部計息。逐卡各自使用，沒填的卡以整筆欠款計。第一次記下利息後清掉（R-DUE-03）。不能是負數或超過目前欠款。
- **R-CARD-07** 每期本金 = 總金額 ÷ 期數，除不盡的餘數放在第一期。各期期別 = 第一期期別起，每個月一期。
- **R-CARD-08** 各期費用依費用方式計算：0 利率為 0；每期手續費為固定金額；總額手續費率先算總費用再平均分攤（餘數放第一期）；年利率依當期剩餘本金計息（越後面越少）。
- **R-CARD-09** 刷卡當下**全額佔用額度**：已佔用額度 = 目前欠款 ＋ 未入帳分期本金；可用額度依已佔用額度計算。
- **R-CARD-10** 帳單**每期入帳**：分期消費的記帳（全額）只影響**預算進度**，不會一次全額變成卡債；卡債由各期入帳累加（每期到期時列在本月到期，記下後才變成卡債，R-DUE-01；本金不重算預算，R-ACT-06）。還沒記下的部分不計循環利息，但算進信用卡總負債（R-ACV-03）。未指定卡片的分期由預設卡片入帳。
- **R-CARD-11** 提前清償：未入帳本金一次結清；未到期手續費是否減免各家不同，所以是選項。
- **R-CARD-12** 試算中，分期各期入帳只讓卡債增加，不重複算成支出（消費當月已算過預算）；各期手續費算成支出。
- **R-LOAN-01** 攤還表：每期利息 = 剩餘本金 × 年利率 ÷ 12（四捨五入到元）。本息平均的月付 = 本金 × r ÷ (1 − (1 + r)^−n)（四捨五入）。本金平均每期本金 = 本金 ÷ 期數。只繳利息則最後一期還本金。最後一期一律還清剩餘本金。

**帳戶設定表單**
- **R-AF-01** 名稱必填，且不能與其他未封存帳戶同名。
- **R-AF-02** 新增帳戶時「目前餘額／欠款」必填；編輯時沒有改就不寫入新的校正紀錄。
- **R-AF-03** 進階欄位全部選填。有填才檢查：額度 > 0；結帳日、繳款日為 1–31。
- **R-AF-04** 打開「計算循環利息」才需要：循環年利率、最低應繳比例；繳款方式為固定金額時要填每月繳款。沒打開就不計息。
- **R-AF-05** 貸款打開「攤還條件」才需要：年利率（可為 0）、剩餘期數、每月繳款日、扣款帳戶（必須是現金或存款帳戶）。
- **R-AF-06** 錯誤訊息顯示在該欄位下方；有錯誤時不存檔。

### 4.6 年度計畫的匯入與編輯

兩種輸入方式共用同一套檢查與儲存，結果一樣。

**CSV 格式**（一列 = 一個「項目 × 支付方式」，欄位順序貼近常見的年度預算表）

```
群組,項目,類型,支付方式,時點,日期,可調,追蹤,帳戶,轉入帳戶,備註,現行,1月,…,12月
```

- **R-IMP-01** 表頭用名稱對應，可用別的說法：大類／名稱／收支／付款／時間／發生日、扣款日、幾號／彈性／控管／入帳帳戶／轉入／說明／全年；月份可用 `1月` 或 `一月`。認不出來的欄位忽略；缺少「項目」或「類型」就整份不收。
- **R-IMP-02** 分隔符號自動判斷逗號或 Tab（可以直接從 Excel 貼上），支援雙引號跳脫、CRLF 與 BOM。
- **R-IMP-03** 金額允許 `$`、逗號與空白；空白、`-`、`—` 視為 0；小數四捨五入到元；看不懂就報錯並指出列號與月份。括號或前置負號解析為負數，但**計畫金額不能是負數**，報錯「退款或收入請另列一個項目」（與 R-EDT-03 相同）。
- **R-IMP-04** 同一個「群組＋項目」的多列合併成一個項目的多個計畫列（例如生活費的現金列與信用卡列）。同一個支付方式出現兩次就報錯並列出兩個列號。項目層級的欄位（類型、時點、日期、可調、追蹤、帳戶、轉入帳戶）後面的列有填卻和第一列不同時報錯，不默默取第一列。
- **R-IMP-05** 帳戶用名稱對應（先完全相同，再前綴相同；只看未封存帳戶）：收入要有入帳帳戶，轉帳要有轉出與轉入帳戶且不能相同，找不到帳戶就報錯；**對到好幾個帳戶**（例如「信用卡」對到信用卡 A 與 B）也報錯，請填完整名稱。支出一定要有支付方式；收入與轉帳填了支付方式會被忽略並提醒。
- **R-IMP-06** 值的對應：類型＝收入／支出／轉帳；支付方式＝現金／信用卡／轉帳；時點＝上半月／下半月／其他（預設上下各半）；可調＝是／否；追蹤＝每月固定（舊檔的「自動計入」也可以）／依記帳／每週回報／到期確認（預設每月固定）。
- **R-IMP-07** 「現行」只用來檢查：與 12 個月合計不符時警示並列出差額。整列 0 顯示提示。
- **R-IMP-08** 先預覽再寫入：預覽列出項目數、計畫列數、全年收入與支出、刷卡金額、會新增的群組，以及所有錯誤與警示。**有任何錯誤就不能匯入**。
- **R-IMP-09** 兩種匯入方式：
  - 更新檔案中的項目：檔案裡出現的項目，該年度金額以檔案為準（檔案沒有的支付方式列清成 0）；檔案裡沒有的項目保持不動。項目的「額外還款」設定保留。
  - 只新增：已存在的項目跳過。
- **R-IMP-11** 讀檔時自動判斷編碼：有 BOM 或是合法 UTF-8 就用 UTF-8，否則當成 Big5（Excel 繁中另存的 CSV）。預覽顯示判斷出的編碼。匯出與範本一律存 UTF-8 加 BOM，Excel 直接打開不會亂碼。
- **R-IMP-10** 匯出：空白範本，或把目前計畫匯出成同一個格式，改完可以再匯回來（來回不會變動金額與日期）。
- **R-IMP-12** 日期欄（選填）：`15`、`15號`、`15日` 都可以；要是 1–31，否則報錯。

**App 內編輯**
- **R-EDT-01** 金額快捷：12 個月同額、只填指定月份（例如 3、9 月）、整列調整百分比（四捨五入、最低 0）、年金額平均分 12 個月（餘數放最後一個月）、清空。
- **R-EDT-02** 快捷（同額、指定月份、調整百分比、平均分）算出負數時當 0；**自己輸入的負數不會被改掉**，存檔時依 R-EDT-03 報錯。
- **R-EDT-03** 存檔前檢查：項目名稱不可空白、要有 12 個月金額、金額不可為負；12 個月都是 0 只提示（不會出現在試算裡）。
- **R-EDT-04** 支付方式由使用者自己設定：一個項目可以有多個支付方式列（例如生活費的現金列與信用卡列），也可以讓不同月份走不同支付方式（在不同列填該月金額）。
- **R-EDT-05** 項目必填：名稱、群組（既有群組，或輸入新群組名稱；新名稱與既有群組相同時沿用既有群組）。同一群組內未封存的項目不能同名。
- **R-EDT-06** 支出每一列都要選支付方式，且同一個支付方式只能一列；把某列改成另一列已經在用的支付方式時，兩列**交換**支付方式（金額跟著列走）。至少保留一列；「加現金列／加信用卡列／加轉帳列」只列出還沒用到的支付方式。
- **R-EDT-07** 收入要選入帳帳戶（現金或存款）；轉帳要選轉出與轉入帳戶，兩者不同。收入與轉帳只有一列、沒有支付方式。
- **R-EDT-08** 切換類型：支出改成收入或轉帳時，各列金額逐月相加成一列；改回支出時成為現金列。
- **R-EDT-09** 月份金額空白為 0；看不懂或負數時指出是哪一列的幾月。金額存到畫面上選的年度。日期（選填）要是 1–31。提醒（不擋存檔）：12 個月都是 0、可調項目卻選「每月固定」、每月固定沒填日期（上半月當作 1 號、下半月當作 16 號到期）、轉給依合約繳款的帳戶卻沒勾額外還款（R-PAY-01）。
- **R-EDT-10** 封存從**本月**起生效：本月以後不再出現在計畫、記帳、本月到期與試算；之前月份的計畫與紀錄仍算在歷史報表（年度彙總只算封存月份之前）。取消封存時清掉封存月份。
- **R-EDT-11** 項目已經有記帳時，**類型不能改**（舊記帳的類型會對不上），報錯「已經有記帳，不能改成○○；請新增一個項目」；畫面上類型 chips 停用。

### 4.6.0 設定與修改記帳

**設定（R-SET）**
- **R-SET-01** 安全線：0 以上的金額。本期提醒、試算安全線、反推都用它。
- **R-SET-02** 預設期間：12／24／36 個月，本期水位圖與試算的預設期間；試算畫面仍可暫時切換。
- **R-SET-03** 每週檢查日：當天距上次檢查超過 0 天就提醒「開始檢查」（其他日子仍是 7 天）。
- **R-SET-04** 刷卡入帳延遲 0–14 天（R-CHK-06 用）。
- **R-SET-05** 記帳時指定信用卡（開關）；**沒指定卡片的刷卡算在哪張卡**（預設卡片：記帳沒選卡片、計畫裡的刷卡、沒指定卡片的分期都算在這張卡，利息與繳款也照這張卡的條件；「自動」為排序第一張卡）；付現金與轉帳時扣哪個帳戶（「自動」顯示實際會用的帳戶；選的帳戶封存後報錯）。
- **R-SET-06** 匯出完整備份、從備份還原（R-DATA-03–06）；載入示意資料、清除所有資料：都要再確認一次，並提醒先匯出備份。

**修改記帳（R-REC-EDIT）**
- **R-REC-EDIT-01** 可以改日期（不能晚於今天）、金額、項目（只能換成同類型的項目）、付款方式與卡片、備註；類型不能改。
- **R-REC-EDIT-02** 自己記的金額要大於 0；原本就是負數的退款可以改成其他負數；對帳差額與到期確認補記可以是負數；都不能是 0。循環利息、貸款利息這類系統算出、沒有付款方式的支出，修改時不要求選付款方式。
- **R-REC-EDIT-03** 付款方式改成現金或轉帳時，扣款帳戶依設定；改成信用卡時用選的卡（或不指定）；付款方式沒變時保留原本帳戶。收入與轉帳換項目時帶入新項目的帳戶。
- **R-REC-EDIT-04** 保留 id、來源、分期與**寫入時間**，所以和餘額校正的先後關係不變。日期移到帳戶上次校正之前時提醒「這筆不會再改變它的餘額」。
- **R-REC-EDIT-05** 分期消費只能改日期、項目、備註；金額與付款方式要刪掉重記。**只有刪除分期消費本身**才整筆取消分期：消費、已入帳各期的本金與手續費、未入帳的各期一起刪。刪除某一期的本金或手續費只刪那一期（R-REC-EDIT-07）。
- **R-REC-EDIT-06** 到期確認與到期記下的款項綁著某個月份的某個計畫列：只能改金額、**同一個月內**的日期與備註；不能換項目或付款方式（要換請刪掉再自己記一筆）。識別碼保留，所以改過也不會再列出一次。
- **R-REC-EDIT-07** 刪除記帳時要做的事由規則算成「刪除計畫」，資料層在同一個交易內照做：
  - 到期確認的補記：同一列同一月沒有其他確認補記時，撤銷「已完成」，下次檢查會再問。
  - 延期款的付款：延期款改回未付清。
  - 到期記下的（R-DUE）：同一組的記帳一起刪（貸款的本金與利息、分期同一期的本金與手續費），回到本月到期清單，可以重新記下；貸款剩餘期數加回一期；刪的是第一次的循環利息時，恢復原本的既有卡循。刪除確認視窗會說明。

**紀錄（R-REC）**
- **R-REC-01** 本月漏記：本月漏記差額（正數）的筆數與合計，顯示在本期的本週檢查提醒下方。
- **R-REC-02** 來源標示：退款、漏記差額／多記差額、到期確認、延期款；到期記下的依種類標每月固定、貸款月繳、繳卡費、循環利息、分期入帳、分期手續費；自己記的正數沒有標示。月摘要的支出不含分期本金入帳（R-ACT-06）。
- **R-REC-03** 補登找回的單據：記帳時如果同一項目、同一支付方式、同一個月有對帳產生的**漏記差額**，會先問這筆是不是那筆漏記；選「是」就用這筆明細取代漏記差額。明細沿用差額的日期與寫入時間（對帳前就發生了，餘額不會再扣一次），差額扣掉這筆（扣完為 0 就刪掉）；明細比差額大的部分是新的花費，照今天記。在同一個交易內完成。

**計畫月份表格（R-PLN-02）**
- **R-PLN-02** 依群組排列，每個「項目 × 支付方式」一列（12 個月都是 0 的列不顯示），附全年合計；依貸款攤還與信用卡循環條件自動產生的繳款另列「貸款與卡費（依條件估算）」＝繳卡費＋貸款合計 − 自己填的轉帳。最後是收入合計、刷卡消費、非刷卡支出、循環利息（估）、繳卡費＋貸款、月現金流（負數紅字），數字與計畫摘要一致。今年的當月欄加底色。

**資料保護（R-DATA）**
- **R-DATA-01** 1.0.0 的資料庫為第 1 版。之後結構改變時提高版本，並寫升級 SQL；升級時保留所有資料。**任何情況都不自動清除資料**（沒有「破壞性重建」）。
- **R-DATA-02** 自動檢查：對照每個版本匯出的 schema，每次升級都要有 migration；新增的欄位與資料表都要有對應 SQL；不允許直接刪欄位；新增的 NOT NULL 欄位要有預設值。**降版保護**：開資料庫之前先讀版本，手機上的資料如果是較新版 App 寫的（例如裝回舊版 APK），不打開、不清除，顯示「資料是新版 App 建立的」畫面，請使用者裝回新版。
- **R-DATA-03** 完整備份（設定 → 匯出完整備份）：一個 JSON 檔，包含帳戶（含封存）、所有餘額校正、群組、項目、各年度計畫金額、到期確認狀態、記帳（含識別碼）、分期（含已結清）、情境、檢查紀錄、**選了「這個月沒有」的到期項目識別碼、延期款**與設定（含預設卡片、到期項目起算日），保留原本的 id。檔名 `MyFSL-備份-YYYYMMDD.json`。
- **R-DATA-04** 從備份還原：先讀檔檢查再確認。不是 MyFSL 備份、檔案損壞、來自較新版本、id 重複時拒絕並說明；對不上的資料（項目的群組不存在、記帳的項目／帳戶／分期不存在）列為注意；項目不存在的計畫金額、帳戶不存在的餘額校正、項目不存在的延期款略過。有對不上的資料時，確認視窗改為「救援還原：有些資料對不上」，列出會被略過或對不上的資料，按鈕為「仍要救援還原」。
- **R-DATA-05** 確認畫面顯示備份時間、帳戶／項目／記帳／分期／情境數量與注意事項，並說明目前資料會被取代。
- **R-DATA-06** 從備份還原的流程：① 先把目前資料（含設定）寫成 App 私有資料夾裡的**復原紀錄檔**：寫暫存檔、同步到磁碟、改名成正式檔，再讀回比對，確定可以讀才開始改資料；寫不進去就不還原，資料不動。② 資料庫在同一個交易內整份換掉，接著寫設定；兩者都成功才刪紀錄檔。③ 途中出錯：馬上用紀錄放回資料庫與設定，放回成功才刪紀錄；放回也失敗時紀錄保留。④ 途中程式被關掉：下次開 App 先檢查紀錄檔，**放回完成前只顯示「正在檢查資料…」，不開放任何操作**；放回成功後提示「上次從備份還原沒有完成，已經放回還原前的資料」。⑤ 放回失敗或又中斷：紀錄仍保留、不刪任何資料，畫面只顯示說明與「重試」；放回是整份覆蓋，重試幾次結果都一樣。⑥ 還有沒放回的紀錄時不能開始新的還原。可接受 Excel 或編輯器加上的 BOM 與未知欄位。

**正式版（R-REL）**
- **R-REL-01** 第一次開啟（還沒看過歡迎頁，且沒有帳戶與計畫）顯示歡迎頁：三步驟說明、資料只存在手機、試算不是財務建議；「開始設定帳戶」到帳戶頁、「先用示意資料看看」、「我有備份檔，要還原」到設定頁。選過就不再出現。
- **R-REL-02** 備份提醒：有自己寫入的資料（寫入時間是真實時間的記帳、餘額校正，或做過本週檢查）且從沒備份、或距上次匯出完整備份滿 30 天時，本期頁最上方顯示提醒，點了開設定。只有示意資料時不提醒。匯出成功後記錄日期。
- **R-REL-03** 當機時把最後一次錯誤（版本、時間、Android 版本、執行緒、最多 60 行堆疊，不含帳務資料）存在手機；「設定 → 關於」顯示並可複製或清除。關於另顯示版本與「不連網、不上傳、不是財務建議」。
- **R-REL-04** Android 系統備份（Google 帳號雲端備份）與換機轉移設定為包含資料庫與設定，但**是否真的備份由手機的系統設定決定**，App 無法保證；可靠的備份是 App 內「匯出完整備份」，由使用者自己保管。除錯版套件名稱加 `.debug`，可與正式版並存。

### 4.6.1 本期總覽（R-OVW）

- **R-OVW-01** 時間進度 = 今天 ÷ 當月天數（四捨五入到整數百分比）。
- **R-OVW-02** 水位迷你圖用現況（不含情境）的每月最低水位；顯示整段期間最低水位與月份；首次低於安全線時顯示「約 N 個月後低於安全線」。個別扣款帳戶會變成負數時另外提醒（R-FC-12）。
- **R-OVW-03** 本週檢查提醒：`上次 N 天前`（從沒檢查過顯示「還沒檢查過」）· 到期確認項數 · 對帳帳戶數；距上次 7 天以上或從沒檢查過時按鈕為「開始檢查」，否則為「再檢查一次」。下方顯示本月漏記（R-REC-01）。
- **R-OVW-04** 本月可調支出依 R-BUD-06 排序，先顯示 4 列，可展開全部。
- **R-OVW-05** 接下來到期：今天起 3 個半月期內的收入、固定支出、繳卡費、貸款繳款；不含可調支出與刷卡消費（刷卡要等繳卡費才動到現金）。依期別、同期金額大的在前，最多 8 筆。

### 4.7 現金水位試算

**基準線（現況）**
- **R-FC-01** 從今天所在的半月開始，共「試算期間 × 2」期。起始餘額為各帳戶目前推算餘額，**每張信用卡各自一個帳戶**；未指定卡片的刷卡（R-ACT-05）加在預設卡片上。沒有任何卡片卻有刷卡計畫時，用一張不計息的替代卡片。
- **R-FC-02** 未來月份使用計畫金額，依日期（沒填依時點）放入期別。支出由支付方式對應帳戶扣款，刷卡算在預設卡片；轉帳照項目的轉出與轉入帳戶；轉給依合約繳款的負債依 R-PAY-01 不計。
- **R-FC-03** 到期的款項（R-DUE-06）：起算日（含）以前到期的視為已在餘額裡；之後到期、已經記下的不再預測；到期了還沒記下的放在今天所在的半月；本月還沒到期的依到期日放。
  - 每月固定：本月以前依本月到期清單（扣掉自己已經記的），之後的月份依計畫與日期。
  - 其他追蹤方式的當月：已完成或已延期 → 0；否則計畫 − 實際（最低 0），日期已過的份額移到今天所在的半月。
  - 延期款依 R-DEF-03。
- **R-FC-04** 今天在下半月時，上半月不再產生事件（併入 R-FC-03 的「日期已過移到今天所在的半月」）。
- **R-FC-05** 有攤還條件的貸款自動產生每期本金（轉帳）與利息（支出）：從起算日之後的第一個繳款日起，跳過已經記下的月份，依目前餘額與剩餘期數攤還；到期了還沒記下的放在今天所在的半月。
- **R-FC-06** 未結清的分期，還沒記下的各期（到期了還沒記下的放今天所在的半月）在入帳期別產生兩筆事件：本金（只增加卡債，不算支出）與手續費（算支出）。停止排程繳款不會停掉分期入帳。試算期間之後才入帳的本金算進期末總負債（R-FC-10）。
- **R-FC-07** 有循環條件的信用卡**逐卡**（R-CARD-03），從起算日之後的每個計息與繳款日（已經記下的月份跳過；到期了還沒記下的放今天所在的半月）產生兩筆事件：
  - 循環利息：刷在這張卡上的支出，金額由當時欠款算出（第一次用既有卡循）；不算進「刷卡消費」，另計為「循環利息」。
  - 繳卡費：固定金額（不超過欠款）／最低應繳（由當時欠款算出）／當期全額（連利息一起清掉），從這張卡的扣款帳戶扣。
  同一個半月內的處理順序見 R-ORD-01。

**模擬引擎**
- **R-FC-08** 每期依 R-ORD-01 的順序處理：利息依當時欠款計算；「全額清償」金額 = 當時目標帳戶欠款，為 0 則略過；轉給負債的款項最多到欠款為 0（R-PAY-02）；其餘依收入、支出、轉帳更新餘額。流動帳戶之間互轉不算流入流出。
- **R-FC-09** 保守最低水位 = 期初流動資金 + 當期新借款撥款 − 當期流出（同一半月內支出視為發生在收入之前，撥款視為期初到位）。
- **R-FC-10** 結果：
  - 最低水位與所在期別；首次低於安全線；首次為負。
  - 期末流動資金、期末卡債（各卡合計）、期末貸款、**期末總負債 = 卡債 ＋ 試算期間之後才入帳的分期本金 ＋ 貸款與保單借款**。
  - 每年結構缺口 = round((收入 − 支出 − 貸款本金還款) × 24 ÷ 期數)；第一期只剩半個半月時仍以整期計算。
- **R-FC-11** 圖表：每月取兩個半月中較低的最低水位，換算千元四捨五入（.5 往正方向）；右端標籤以「萬」表示（`−4.9萬`、`5萬`）。「約 N 個月後」= 兩期別的年月差。
- **R-FC-12** 扣款帳戶不夠扣：總水位夠、但某個流動帳戶會變成負數時（例如現金帳戶只出不進），本期顯示 `「零用現金」約 2026/10 會不夠扣款，記得先從其他帳戶轉入`，比較表的「扣款帳戶不足」列出期別與帳戶。

**情境**（依清單順序套用在基準線上）
- **R-SC-01** 調整項目：從起始期起，指定項目金額 × (1 + 百分比)，四捨五入、最低 0。調整、停止、改支付方式**只作用在計畫產生的事件**；既有分期、延期款與合約繳款是已經發生的義務，不會因為「之後少花一點」而變少。
- **R-SC-02** 停止項目：從起始期起刪除該項目的事件。
- **R-SC-03** 改支付方式：從起始期起，指定項目中原支付方式的支出改為新支付方式與其扣款帳戶。
- **R-SC-04** 一次性收支：收入入指定帳戶；支出依支付方式扣款，沒有支付方式則用指定帳戶。
- **R-SC-05** 清償負債：
  - 在指定期別全額清償；**每張卡各自一筆**清償（金額 = 那時那張卡的欠款）。只清其中一張時，另一張的欠款與條件照舊。
  - 可同時停止這些帳戶從該期起的排程繳款：計畫中的繳卡費、貸款的本金與利息（分期入帳不算排程繳款，不會被停掉）。**卡片的合約（計息與繳款）照舊**：清償後欠款是 0 就不會有利息與繳款；之後還有新刷卡或保留的分期時，新欠款依原條件計息與繳款。同一個半月內先計息、再清償（R-ORD-01），所以清償金額含當期利息。
  - 預設一併結清未到期的分期：未入帳本金一次付掉，之後不再入帳；這筆錢從流動資金出去，但不算成新的支出。
  - 清償後同一半月的刷卡成為新的卡債。
- **R-SC-06** 新增貸款：
  - 在起始期撥款入帳。
  - 從下個月的指定半月開始依攤還表繳款；超出試算期間的期數不列入。
  - 情境中的貸款帳戶使用負數 id（−1000 起）。

**反推目標**
- **R-GS-01** 目標為「最低水位不低於 X」或「結構缺口不小於 0」，只調整選定的項目。
- **R-GS-02** 不需調整即達標 → 0%；全部砍掉仍未達標 → 100% 並標為做不到；否則二分搜尋 40 次，結果**無條件進位到 0.1%**。
- **R-GS-03** 同時列出每個項目每年需減少的金額 = 期間內金額 × 百分比 × 24 ÷ 期數。
- **R-GS-04** 特殊情況直接說明，不做搜尋：沒選項目或選的項目在開始之後沒有計畫金額 → `選的項目在這段期間沒有可以減的計畫金額（既有分期與延期款不會被減），請換別的項目。`；全砍也達不到、且最低點發生在開始減少之前 → `最低點發生在下個月開始減少之前，怎麼減都來不及；要先處理這個月的現金（例如延後付款或轉入存款）。` 只調整計畫產生的事件（R-SC-01）。

**情境編輯（R-SCN）**

- **R-SCN-01** 情境必填名稱，至少一個變動。每個變動選「從哪個月開始」（本月到 12 個月後）；換算成該月上半月的期別，但不早於今天所在的期別。
- **R-SCN-02** 可加的變動：調整支出（百分比，減少填負數，可複選項目，預設全部可調支出）、**貸款整合卡債**、新增貸款、清償負債、改支付方式、一次性收支、停止項目。
- **R-SCN-03** 貸款整合卡債 = 新增貸款（撥款到選定帳戶）＋ 同一期用撥款帳戶清償選定的負債（預設所有信用卡、一併結清未到期分期、停止原本的繳款計畫）。存檔時是兩個變動，打開編輯時合併回一個。
- **R-SCN-04** 檢查：貸款金額 > 0、年利率 0–100、期數 1–480、撥款與扣款帳戶是現金或存款、至少一個要清償的負債；改支付方式的前後不能相同；一次性收入要入帳帳戶，支出要支付方式。
- **R-SCN-05** 比較表：現況與每個情境的最低水位（與月份）、首次低於安全線、扣款帳戶不足（R-FC-12）、年結構缺口、期末卡債、期末總負債、循環利息合計；各列最好的數字加粗，負數與會低於安全線的標紅。
- **R-SCN-06** 反推：目標「不低於安全線」或「每年收支打平」，選要減的項目（預設可調支出），從下個月起算。結果顯示要減的百分比、各項目每年少多少、減完後最低水位；達不到時說明要搭配其他做法。可「存成情境」。

### 6.5 循環信用（獨立示意數字，不影響設計稿）

卡債 $400,000、循環年利率 15%、最低應繳 10%（下限 $1,000）、每月刷 $20,000（上下半月各 $10,000）、計息與繳款日 15 日（上半月），今天 9/1：

| 繳款方式 | 當期利息 | 當期繳款 | 上半月底卡債 | 整月卡債變化 | 兩年後 |
|---|---|---|---|---|---|
| 最低應繳 | $5,000 | $40,500 | $374,500 | −$15,500 | 卡債逐月下降 |
| 固定 $3,000 | $5,000 | $3,000 | $412,000 | +$22,000 | 卡債持續變多 |
| 當期全額 | $5,000 | $405,000 | $10,000（清掉後同一半月新刷的） | 月底只剩當月新刷 $20,000 | 每月都把前一期欠款全部繳清，但月底新刷的欠款到下個月計息日仍會計息（例如 20,000 × 15% ÷ 12 = $250） |

- 最低應繳的第一期：利息 $5,000 先加上去（餘額 $405,000），最低應繳 = $40,500，還到本金 $35,500；上半月再刷 $10,000，上半月底 $374,500；下半月再刷 $10,000，整月變化 = 20,000 + 5,000 − 40,500 = −$15,500。
- 固定 $3,000：整月變化 = 20,000 + 5,000 − 3,000 = +$22,000（上半月只有 10,000 + 5,000 − 3,000 = +$12,000）。
- 借貸款一次清掉卡債、之後刷卡改現金時，就不再產生循環利息；若之後還有刷卡，新欠款依原條件計息（R-SC-05）。

| 37 | 只繳利息的貸款記下後仍列為未付 | 重複列出、試算重複預測 | 同一組識別碼任何一個記下就算完成（R-DUE-04） |
| 38 | 未指定卡片的刷卡沒算進到期利息的基準 | 利息少算，和試算不一致 | 起始欠款和試算相同（R-DUE-01） |
| 39 | 一筆沒規劃支付方式的付款被多個計畫列重複抵扣 | 未付金額少算 | 依計畫列順序分配，每筆只抵一次（R-DUE-04） |
| 40 | 本週檢查略過前一項後，後面的建議金額不變 | 全額繳款多算利息 | 依實際選擇往下算，預覽與寫入一致（R-DUE-05） |
| 41 | 試算引擎沒有照 R-ORD-01 的順序（分期在最後） | 同一期利息少算 | 引擎用完整順序表；情境清償和合約全額繳款分開（R-FC-08） |
| 42 | 循環利息、貸款利息的記帳連備註都不能改 | 被「請選付款方式」擋下 | 沒有付款方式的系統記帳不要求（R-REC-EDIT-02） |
| 43 | 刪除第一次利息後既有卡循沒有恢復 | 重記時利息變大 | 記下時保存原值，刪除時恢復（R-REC-EDIT-07） |
| 44 | 還原只靠記憶體裡的備份 | 途中被關掉會留下半套資料 | 磁碟上的復原紀錄，下次開啟放回（R-DATA-06） |
| 45 | 清償情境把卡片之後的計息與繳款整個刪掉 | 之後的新刷卡不計息 | 卡片合約照舊，只停計畫的繳卡費（R-SC-05） |
| 46 | 開 App 時的放回在背景進行，放回前就能操作；還原流程沒有自動測試 | 可能在不一致的資料上記帳 | 放回完成前只顯示檢查中、失敗時只能重試；流程抽成 RestoreCoordinator 並用假的資料庫測中斷與失敗（R-DATA-06） |

另有 2 項是測試本身的預期寫錯，程式行為正確，已修正測試：汽車保養每年 9 月都有計畫；清償後同一半月的刷卡仍會形成卡債。
